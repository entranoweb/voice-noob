# Differences between the models and the migrated database that existed when
# the drift check was added (25 November 2026). See app/db/migration_drift.py.
#
# The check fails on any difference NOT listed here, and on any line here that
# no longer matches. So this file can only shrink: fix a difference with a
# migration (or by correcting the model), then delete its line.
#
# Do not add a line to make a red build green. A new line means a model and a
# migration disagree, and the tests cannot see it because they build their
# schema from the models.
#
# What is in here, most serious first:
#
# 1. Columns the migrations made ARRAY or JSONB and the models declare JSON
#    (modify_type). Two are arrays (campaigns.calling_days, test_scenarios.tags):
#    the tests write to a JSON column, production writes to an array column.
# 2. Unique indexes that exist only in the database (remove_index ... unique):
#    contacts by (user_id, email) and (user_id, phone_number), and
#    user_integrations by (user_id, integration_id). The tests cannot hit them.
# 3. Foreign keys that cascade on delete in the database and not in the models
#    (remove_fk ... ondelete=CASCADE paired with add_fk ... ondelete=None).
# 4. Plain indexes and one unique constraint the migrations created and the
#    models do not declare (remove_index, remove_constraint). Harmless at run
#    time, but autogenerate would drop them.
